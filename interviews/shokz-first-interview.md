# 韶音科技一面面经

> 来源：AI 语音转文字。本文仅对原始内容进行了 Markdown 排版和标点整理。

## 面试问题

1. 请用两分钟介绍这个 Agent 项目：它解决什么业务问题、你个人负责哪些模块？

2. 中心调度 Agent 的输入、输出和核心职责分别是什么？哪些事情由它决策，哪些事情由规则或代码决定？

3. 为什么采用“中心调度 Agent + 多个 Skill”的架构，而不是单 Agent、固定 Workflow 或普通后端服务编排？这个选择有什么代价？

4. 如果中心调度 Agent 路由错误，把任务分配给了不合适的 Skill，系统如何发现、纠正并避免反复路由？

5. 请用一个真实用户请求，完整讲述从请求进入、意图识别、任务拆解、Skill 选择、工具调用、结果校验到最终回复的全过程。

6. 这个 Agent 最常见的失败类型有哪些？请分别举一个模型问题、检索问题、工具问题和业务数据问题的例子。

7. 当现有 Skill 无法完成任务时，Agent 如何判断是“没有合适工具”，而不是“工具选择错了”或“参数生成错了”？

8. 对于无法自动完成的需求，系统如何降级？

9. 项目底层使用了哪些模型？在效果、延迟、结构化输出和数据安全之间是如何权衡的？

10. 如果让你把当前模型替换成更便宜或更快的模型，你会设计哪些回归测试，判断它是否能够安全上线？

11. 项目为什么没有做微调，或者为什么需要微调？

12. Prompt 是如何迭代的？是否做了版本管理、离线评测和 A/B 测试？

13. 如果出现缺字段、类型错误、非法 JSON、Markdown 混入或语义不合法，分别怎么处理？

14. 工具调用过程中如果出现超时、重复调用、部分成功或有副作用的操作失败，系统如何进行重试、幂等控制和补偿？

15. 项目二的整体设计思路是什么？请说明各模块的职责边界、调用关系、共享状态以及为什么要这样拆分。

16. 项目二需要的支撑信息来自哪些数据源？

17. 如果 RAG 文档中明明存在答案，但没有成功召回，请按照排查顺序说明你会检查哪些环节，以及每一步如何验证。

18. 多路召回时，如果关键词检索、向量检索和图检索返回重复或冲突内容，系统如何去重、融合、重排并选择最终证据？

19. 测试集如何构建，Bad Case 如何分类、归因和回归验证？

20. 这个 Agent 是否真实上线？目前的用户量、任务成功率、单次成本和失败率是多少？
